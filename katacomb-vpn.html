Katacomb VPN

Pick a node anywhere. Pay on-chain. Connect.

A desktop client for the Sentinel decentralized VPN network. No accounts and no single provider: you pay independent node operators directly, from a wallet you hold the keys to.

Debian 11+, Ubuntu 20.04+ and derivatives. Installs a small root daemon, so connecting and disconnecting never prompt for a password, and declares its dependencies properly.

Verify and install

  1. Check it

    Put SHA256SUMS and SHA256SUMS.asc next to the download. Import the signing key once, then check the file and the signature:

    gpg --fetch-keys https://keybase.io/proofoftrinity/pgp_keys.asc
    sha256sum -c SHA256SUMS --ignore-missing
    gpg --verify SHA256SUMS.asc SHA256SUMS

    A checksum only proves the file arrived intact: anyone who can replace the download can replace the checksums with it. The signature is what makes it mean something, which is why the key's fingerprint is listed here rather than only on the release. Look for Good signature and check that the fingerprint gpg prints matches this one; its warning that the key is not certified is expected.

    Signing key740A F267 B0D8 162B E477 779D 7315 246A 6E67 F3C6

    SHA256SUMSSignatureKeybase identity

  2. Install

    Install it with apt, which pulls in its dependencies:

    sudo apt install ./katacomb-vpn_1.18.1_amd64.deb

    The install adds you to the katacomb-vpn group. Log out and back in once for it to take effect; until then, connecting asks for your password each time.

Good to know

  • Wallet storage needs an OS keyring. GNOME and KDE ship one; on a bare XFCE or LXQt install, add gnome-keyring. A missing keyring means saving a wallet is refused outright rather than silently falling back to weak encryption.

A look inside

Create or import a wallet, add P2P, then pick a node and connect.

What it does

Everything runs locally against the chain. There is no Trinity server in the path.

Map and node table
A 3D globe with per-country counts, plus a virtualized table over the whole network. Filter by country, city, protocol or bookmarks, sort on any column, and probe latency or test download speed before you spend anything.
Multi-hop
Chain two nodes so the entry sees your IP but not where you go, and the exit sees where you go but not your IP. Candidates are checked against each node's advertised inbounds before anything is paid for, and the exit is paid from a second wallet.
Kill switch
Firewall rules that drop everything outside the tunnel: iptables on Linux, the Windows Filtering Platform on Windows. Armed on connect and torn down on disconnect, with a self-healing marker that repairs stranded rules if the app dies mid-connection.
DNS and split tunneling
Choose a resolver (Cloudflare, Quad9, NextDNS) applied on connect; on the V2Ray-family protocols queries go out over DoH, so the node can't read them. CIDR routes bypass the tunnel, with private ranges excluded by default.
Wallet
BIP-39 import or generate, multiple wallets, subaccounts at a chosen index. Seeds are encrypted at rest with the OS keyring on Linux and with Windows' own data protection (DPAPI) on Windows. If the keyring is unavailable, saving is refused rather than falling back to plaintext.
Provider mode
The other side of the network: register a provider, create and activate plans, lease nodes and read subscriber counts off the chain. An economics strip tracks daily burn, escrowed funds and revenue net of the hub's cut.

Protocols

Each node runs exactly one. The client connects to all five, on Linux and Windows, and refuses nodes advertising any other type.

Hysteria2YesYes—Nosntl-tunuserspace + tun2socksQUIC; refuses to connect without a TLS pin

Multi-hop chains are built on v2ray-core's proxySettings.tag, which the other protocols have no equivalent for. Bundled binaries are SHA-256 pinned; both the app and the root daemon refuse to execute one whose hash doesn't match.

Interface and How it runs are for Linux. On Windows, every protocol runs through the Katacomb VPN service, on Wintun adapters with the same names.

Security model

Node operators are treated as adversaries. Their handshake data turns into configs that wg-quick and iptables execute as root, and a single PostUp line in a WireGuard config is a root shell.

Every config is checked twice

Every node-supplied config passes an allow-list validator first, and anything not explicitly permitted is rejected. The privileged helper re-validates independently, because its socket is the real trust boundary. On Windows the same helper runs as a LocalSystem service behind a named pipe, under the same rules. The renderer runs sandboxed with context isolation and no Node access.

Paying for a session

Connecting spends real funds: a session is a blockchain transaction priced in udvpn and paid to the node operator. Preflight checks run before it is paid for, and a failure on the client side, during the handshake or validation, cancels the session and refunds it automatically. A session you actually used is not refunded. A multi-hop chain is two sessions and two deposits.

What multi-hop does not do

It protects against one dishonest node: with two hops, neither end holds both your identity and your destinations. It does not make you anonymous. Two operators working together can still correlate the circuit on traffic volume and timing, since the same bytes cross both hops at the same moments. That is a hard ceiling, not something a client can close.
